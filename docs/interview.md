# 面试官视角的项目亮点与防守清单

## 90 秒介绍

> 海外客诉里，包装压溃、物流撞击和装配损伤最后都可能写成「到货有划痕」。我把这个问题做成一个 CQE 证据工作台。先并行拉渠道评分、出货追溯和 QMS，再通过可回查的批次和检验记录决定哪些告警可以提交复验。这个仓库能实际跑出同步、失败保留、8D 建议和 Listing 星级情景。公开数据采用合成样例，分类效果和告警延迟可以用脚本复跑。

## 打开页面的演示顺序

1. 点 **同步三源**。指出渠道的 9 页、每源记录数和 77/80 差评追溯覆盖。用剩下的 3 条解释缺引用、未命中和冲突的区别。
2. 展开 **包装内衬压碎**。从原文标记、`TR-LOT-PU-04`、6 件角跌试验中的 3 件复现，讲到 `8D-002` 的 D5 和 CQE 提交复验。问到指纹案例时，指出它只有观察，相关批次仍需物理复现。
3. 点 **回放来源故障**。观察出货追溯返回 503、重试两次，随后打开仍可用的上一成功快照。
4. 展示 [可复跑评测](evaluation.md)。先讲 89.8% Macro-F1 的分母，再讲 11 月 16 日多报的误触信号和语义长尾漏判。

## 追问与回答

| 面试官问 | 应答要点 | 现场证据 |
| --- | --- | --- |
| 评论里没供应商，你怎么找到的？ | 渠道记录只有可空的追溯引用。需再核对出货记录的 SKU 和时间。缺引用、未命中、冲突分别计数。供方字段表示关联对象，正式责任判定走质量流程。 | [关联代码](../service/traceability.py) · 三源快照 |
| 两个硬件问题都像「到货损坏」，怎么避免乱归因？ | 模型只输出允许的标签与原文片段。包装压溃看内衬，物流撞击看承运和外箱证据。现场检验按 SKU、批次和失效代码关联。先开调查，再凭同批次复现提复验。 | [标签协议](../core/tagger.py) · `QMS-26-117` |
| 模型能引用真的词却打错标签吗？ | 能。结构和原文校验约束可回查性，已知模式还有额外门槛。低温指纹需要指纹、低温、识别下降三个要素。复杂否定、多故障评论和跨语种长尾仍要用盲标集校准。 | [模型反例测试](../tests/test_demo.py) · [分类错例](evaluation.md) |
| 为什么用这种检索，不堆向量数据库？ | 5 案例的首要约束是同类和时间边界。先按双语 TF-IDF 找词义相近的候选，再按证据词覆盖与失效码重排。用户看到已有 D4/D5/D6。扩库后再拿稀疏、向量和混合方案做同集对比。 | [检索代码](../core/rag_8d.py) · 17 条检索标注 |
| 拉到第八页接口挂了或者重启怎么办？ | 同一分页只接受稳定快照。429、5xx 和传输故障有重试预算，页数、游标和总耗时有边界。只有三源齐备才提交快照。重启标记未结束任务，已有快照保持可读。 | [HTTP Adapter](../adapters/http_feeds.py) · [状态与事务](../service/run_store.py) |
| 用户点两次提交，会产生两条研判吗？ | 创建同步用幂等键。研判用期望版本，陈旧版本返回 409。调查与移交记录都归属于具体 run 和 case，正式结案留给 QMS。 | [契约接口](integration.md) · [并发与版本测试](../tests/test_sources.py) |
| 89.8% 能代表线上效果吗？ | 分母是仓库内 58 条有人工标签的合成挑战样本，含待复核。检索 1.000 来自 5 案例及 11 个有答案的检索题。下一步要跨渠道、机型和月份做独立盲标，并以人工确认和销量分母回放。 | [评测结果与数据](evaluation.md) |
| 实际把 Amazon 提高了 0.4 星吗？ | `+0.4★` 来自样本情景。假设近七天评价量与分布延续，且相关后续低星有 70% 改善到五星。差值比较的是整改与未整改两种 30 天情景。实际效果要观察曝光、销量、星级和整改措施，并做同期对照。 | [情景代码](../core/listing_metrics.py) |
| 距离企业上线缺什么？ | 当前是单进程本地工作台和公开合成演示。企业接入需要真实 OAuth 或相应授权、映射覆盖、分环境密钥、身份与权限、日志留存和业务验收。 | [接入契约](integration.md) |
